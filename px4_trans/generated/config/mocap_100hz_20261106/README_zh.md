# 动捕100 Hz与延迟补偿复测配置

地面站默认发送频率从50 Hz提高到100 Hz。flight.mocap_attitude_rate_hz支持10–100 Hz且不超过control.rate_hz，默认100；配置50可恢复旧发送上限。源样本不足时不会重复发送，也不会补发积压包。

对log_1_2026-11-6-11-04-54.ulg分段匹配机体系角速度，结果如下。负号表示相应动捕姿态的运动实际更早发生。

| 飞控时间段 | 最佳偏移 |
|---|---:|
| 25–30秒 | -12.33 ms |
| 30–35秒 | -13.36 ms |
| 35–40秒 | -13.59 ms |
| 40–45秒 | -14.21 ms |

据此采用10 ms补偿作为保守初值；不把该值解释为纯无线时延。EKF入口还会扣除半个积分周期，新预测周期5 ms对应约2.5 ms，因此不能把原始角速度对齐结果原样叠加到EV_DELAY。

在地面未解锁时执行apply.nsh中的三条命令，保存后重启：

```sh
param set EKF2_EV_DELAY 10
param set EKF2_PREDICT_US 5000
param save
```

EV_CTRL=16、EVA_NOISE=0.05、DELAY_MAX=200 ms等当前设置保持不变。重启是为了重新分配与预测周期匹配的缓冲区。此次不要求刷入新固件：上一版日志减负固件已有这些参数和100 Hz接收能力。

当前预测周期10 ms时，观测限频间隔约10 ms，带有8–17 ms采样间隔抖动的100 Hz观测可能被大量丢弃。改为5 ms可同时提高处理频率和缓冲分辨率。新增单元测试验证200 ms延迟缓冲下，1秒约100次有效完整姿态更新。

100 Hz的姿态协议流量约4.8 kB/s。两个按发布频率记录的日志主题（动捕姿态、三轴辅助源状态）合计新增约11.4 KiB/s，继续不记录FIFO。

检查：

```sh
param show EKF2_EV_DELAY
param show EKF2_PREDICT_US
gs_link status
listener logger_status -n 1
listener cpuload -n 1
```

更新并重启地面站后，以新日志实际计算观测到达频率、融合更新频率、创新/拒绝率、CPU负载和dropouts。提高预测频率增加计算量，已有模拟测试不代表实体机负载已验证。对同一套缓慢/快速分轴动作复测，若创新没有改善可恢复EV_DELAY=0、PREDICT_US=10000、地面站发送50 Hz。

当前工作环境未发现可访问的飞控串口，参数命令仅已准备，尚未写入实体机；没有重启运行中的地面站或飞控。
