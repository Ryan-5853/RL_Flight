# 机架A“失去roll控制权限”诊断

机载：log/26.11.6/log_0_UnknownDate.ulg。
对应地面站：flight_20261106T035442_144Z_aircraft-01_1.csv，VRPN sensor 1，RC手动控制，外环未接管。

## 结论

飞行中不是roll控制输出被关闭，也没有持续舵机端点饱和。机载控制器能跟随自身坐标中的roll目标，但机载姿态基准与机架物理姿态存在约8–10°的roll偏差、约8–11°的pitch偏差，左滚10°指令范围被这个偏差基本占满，表现为满左杆仍无法获得预期的真实左倾。

高度可疑且直接相关的是本机SENS_BOARD调平补偿：X_OFF=8.98745°，Y_OFF=-6.84081°。同时这次外部姿态没有实际融合；虽EV_CTRL=16，但cs_ev_yaw全程false，日志没有vehicle_visual_odometry和estimator_aid_src_ev_att记录。PREDICT_US=10000，与之前机架B的5000也不同，不能把B的工作状态套用到A。

## 证据

1. 起飞前约4.5–6.5秒，动捕转换FRD后roll/pitch约[-0.75°,0.21°]，机载EKF却约[-8.67°,8.24°]。重力方向夹角约11.26°。
2. 此时主加速度计未经CAL_ACC修正的均值约[0.329,-0.036,-9.722] m/s²。板级调平参数会通过R(GetSensorLevelAdjustment())旋转校准后的加速度数据，源码不是仅改变QGC显示。
3. 14–16秒：roll杆接近-1，目标约-9.97°；EKF实际平均-9.74°，误差中位约+0.26°，95分位约+0.54°。三个舵机没有端点饱和。同期动捕roll约-0.57°。
4. 18–22.5秒：目标平均约-10.00°，EKF实际平均-10.04°，95%的roll误差约落在[-0.75°,0.95°]，舵机端点饱和比例0%。所以“满杆但机架不继续向左倾”不能解释为控制器停止跟踪或舵机顶到底；控制器已经认为达到最大左倾目标。
5. 18–20秒动捕roll约-0.46°，21–22.5秒约-0.09°；同时EKF约-10°。飞行中相对姿态差较起飞前继续增大；固定安装外参也可能贡献部分差异，但原地机载大倾角、存储的大调平角、roll范围耗尽和未启用EV的组合证据非常强。
6. 解锁5.7449秒，首次油门输出6.7495秒。约23.1886秒EKF pitch达到30.01°，23.1899秒触发collective attitude limit 30 deg，23.2006秒内部上锁。此处才是真的整个输出被保护关断，而且直接越限的是pitch，不能倒推此前roll权限被关闭。

## 地面站对齐细节

GS-Link遥测pitch字段采用低头为正，与PX4 Euler pitch相反。已在对齐时还原该符号，不能直接用CSV的fc_pitch_deg与PX4 theta比较。

根据三轴遥测姿态匹配时间轴，1413个运动样本一致，时钟偏移中位583526.941427秒，5–95分位残差约-22/+19 ms。时间精度足以支持数秒窗口比较；静止偏差不可能由这一级时延解释。动捕与机架轴安装仍需独立核对，不把CSV的绝对姿态无条件当作完美真值。

本日志无ULog dropout，filter_fault_flags始终0，姿态reset counter全程0。没有roll重置或估计器故障位触发证据。

## 应优先处理

- 将机架物理参考面真正放水平，核对飞控板实际安装方向与SENS_BOARD_ROT，再重新做水平姿态校准；校准后比较实际水平时机载roll/pitch。大补偿可能意味着错误摆放或错误安装配置，但单靠日志无法还原当时校准操作。不要把另一架的调平参数直接复制到本机。
- 查清机架A为何没有外部姿态进入/融合：检查此机的gs_link status mocap会话/采样时间、listener vehicle_visual_odometry和estimator_aid_src_ev_att。参数置16并不代表融合已生效；这份日志不足以区分协议/固件差异、时间同步或地面站路由问题。
- 修正姿态基准后，再验证左右小幅roll指令对应的真实倾斜方向和幅度。暂时不通过扩大10°目标限幅或提高roll增益补偿基准误差。
